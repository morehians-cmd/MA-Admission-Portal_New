**Status:** Approved design; Sheet 9 grade-field order clarified by user on November 18, 2026  
**Repository:** `morehians-cmd/MA-Admission-Portal_New`

**Existing legacy store inspected:** `AdmissionDb.gs` — 117 `AdmissionStudents` headers

## 1. Design conventions

### 1.1 Data types

| Type | Storage convention |
|---|---|
| ID | Text; server-generated UUID-based immutable key |
| FK | Text; references the exact parent ID |
| TEXT | Plain text; trim and length-limit server-side |
| ENUM | Text; must match the controlled values in this dictionary |
| BOOL | Boolean represented consistently as TRUE/FALSE |
| DATE | ISO date `YYYY-MM-DD` |
| DATETIME | ISO 8601 timestamp; generated server-side |
| INTEGER | Whole number |
| URL | Validated HTTP(S) URL, optional unless specified |
| EMAIL | Normalized lowercase email |
| JSON | Not used for core relational data; avoid packing requirement/profile structures into JSON cells |

All sheet headers are exact and ordered as documented. IDs are never generated by the browser. Timestamps and actor identities are server-controlled. Spreadsheet formulas are not authoritative for permissions, status transitions, deadlines, or validation.

### 1.2 Common fields

Where specified:
- `CreatedAt` DATETIME, server-generated.
- `CreatedBy` EMAIL or controlled system actor.
- `UpdatedAt` DATETIME, server-generated.
- `UpdatedBy` EMAIL or controlled system actor.

Do not add common fields indiscriminately to append-only history sheets. History events should be immutable after insertion.

### 1.3 Null and blank handling

- Blank means unknown, not applicable, or not yet supplied; do not invent placeholder values.
- For optional ENUM fields, blank is permitted unless a workflow rule requires a value.
- A boolean must not use arbitrary strings such as Yes/No in one sheet and TRUE/FALSE in another.
- LRN and official identifiers are TEXT, never numeric, to preserve leading zeroes and formatting.
- Sensitive values must be minimized and protected by server-side access control.

## 2. Sheet 1 — AdmissionApplications

**Purpose:** Application master. One row per application, including multiple applications by the same person across different school years.

**Primary key:** `ApplicationID`

**Unique constraints:** `ApplicationID`; no global StudentID+SchoolYear uniqueness rule is imposed.

| Column | Type | Required | Rule |
|---|---|---:|---|
| ApplicationID | ID | Yes | Immutable |
| StudentID | FK | No | Blank until permanent student identity is legitimately created at enrollment |
| UserID | FK/TEXT | Yes | Applicant account identifier; never trust browser-supplied ownership |
| SchoolYear | ENUM/TEXT | Yes | Consecutive school-year format, e.g. 2026-2027 |
| IntakeMethod | ENUM | Yes | ONLINE, WALK_IN |
| GradeLevelApplied | ENUM | Yes | Approved K–12 grade list |
| Department | ENUM | Yes | PRESCHOOL, ELEMENTARY, JUNIOR_HIGH, SENIOR_HIGH |

**Integrity:** An application is not an enrollment. Do not create an `AdmissionStudents` row, permanent StudentID, or official MA identifier merely because an application is submitted or approved.

- Requirement verification and conditional-enrollment authorization are separate.
- A requirement cannot be marked VERIFIED merely because conditional enrollment was authorized.
- Only Admissions-authorized staff can perform final verification.
- The requirements catalog/matrix is versioned and derived from the temporary AdmissionPortal-Backup baseline.

## 15. Identifier and relationship rules

- Internal StudentID is the immutable relationship key.
- ApplicationID and RegistrationID are distinct workflow identifiers.
- Official MA/MC/TLC/SHS identifiers are stored in StudentIdentifiers, not used as internal foreign keys.
- New applicant: do not create permanent StudentID or official MA identifier until the approved enrollment transition.
- Returning student: preserve existing StudentID and official identifiers.
- Grade/classification changes never change an existing official identifier.
- Only Owner may authorize a change to an issued official identifier; retain the prior identifier history.
- LRN is a 12-digit text value, first digit 1–5; required for new applicant and returning registration; duplicate checks are server-side.
- Do not auto-merge possible duplicate students. Flag for manual verification.
